The manifest is edited in the same inspector: /manifest shows the fields of the JSON Schema of manifests (reiwand-ctl scene schema --manifest), generated by schemars from the types of reiwand-format, title first, then description, change notes, version, id, authors, license, content, photosensitive, origin, credits, previews, links, tags, inputs, platforms, display, requires, needed packages and default language, and after them the fields the order does not name (such as gpu). schema, kind, entry, preview, playback, web and permissions, which scenes do not use, and the user properties and presets, which have their own lists, are not shown. display offers what applies to the kind of the package: span and accent for scenes, and fit, background, flip, zoom or position only for the pictures and videos that use them; a value already written there by hand stays visible so that it can be removed. The default language has no way back to a default, since texts in several languages need it. More annotations guide the widgets:

accent has its own control instead of raw JSON, in the inspector of the manifest of scenes and of web pages: a box that chooses between the dominant color of the preview (no value), a fixed color (the color chooser, written as #rrggbb) and the color of a property (a box with the color properties of the package, written as {"prop": "<id>"}). It sends the manifest action display with values.accent, or clear: ["accent"] for none, so reiwand-ctl scene act and scene act DIR manifest '{"display":{"values":{"accent":"prop:ID"}}}' do the same. The action refuses a property that is not a color, a rename of the property moves the accent along, and a property that the accent follows cannot be removed until the accent changes.

The playback group of the manifest is shown for scenes too (their frame rate, volume and muting; the speed, the part and the loop belong to videos). playback.max_fps has a control of its own, a box with Not set, Follow the screen and the usual rates (10 to 240 frames a second) and Another rate… for a number from 1 to 240. It sends the manifest action playback with values.max_fps ("display" or a whole number), or clear: ["max_fps"] for none, so reiwand-ctl scene act and scene act DIR manifest do the same; a rate of 0 or over 240 is refused. The rate only lowers the ceiling of the scene: what the user or the battery sets still wins.

Annotation Meaning
x-markup a text with the markup of package.md, edited on several lines with a view under each one that renders what is typed as the app does everywhere else (paragraphs, lists, bold, italic and links; HTML, images and remote content are not part of the markup, and the links of the view are shown but never followed)
x-required required in reiwand.wpak/3 (content, photosensitive, origin), so it has no way back to a default; a switch that is not set yet shows No and Yes
x-computed filled by the tools (requires.features), shown read-only with translated names but for the features the author chooses
x-ref thumbnail or animated: a file chooser that runs thumbnail; language: the languages of the texts and of the desktop, offered in a list by their names in the language of the desktop

Texts (titles, descriptions, change notes, labels, help, options and preset labels) show one row per language, a plain text under the default language. translate takes only a pointer whose schema is a text and writes where the text lives: a plain text stays plain in the default language or with an empty language, and another language turns it into a map with the plain text under default_locale (set to en when missing); a map gets or loses that key, and the last text of a title cannot go; an "@key" text writes strings.<language>.<key>. A text that does not exist yet starts in the default language. An empty text removes that language, or an optional field when it is plain. The text of a text layer takes the same rule under the default language of the package (a layer that follows a value, such as a clock, has no languages and translate says so, and the last text of a layer cannot go); the inspector shows it as a plain multi-line field with the language box under it until a second language exists, and as one multi-line row per language afterwards. The problem list marks a text layer that lacks the default language. The preview panel has a Language of the preview choice, kept in the look as language, which the live preview and scene render --language use; the editor measures and rasterizes the text in the default language. Translate in the app sends add, which never overwrites a text. Lists of names (authors, tags, the paths of a credit) are edited one per line, lists of choices (inputs, the reasons of a mature rating) as check boxes, and previews with a file chooser.

thumbnail copies a png, jpeg or webp of at most 1024 pixels a side and 1 MiB as it is, and turns a larger picture, or a gif, into a jpeg of at most 1024 pixels as assets/preview.jpg, lowering the quality (85, 75, 65) and then the side (768, 512 pixels) until it fits in 1 MiB, or refusing the picture; an animated preview must already be a gif or webp of at most 640 pixels a side, 15 s and 8 MiB. Files with the same name and other content are kept as preview-2.jpg, and prune deletes the ones no longer named. A preview over its size points at its own field.

Credits have a panel of their own under /manifest/credits: the pictures, videos, sounds, fonts, tables and models of the folder (previews excluded) with a box each, by default only the ones no credit covers, a license (the common ones are offered, any SPDX expression is accepted), who made them and an address, and Credit the chosen files, which sends manifest credit; every credit is listed with a button that sends uncredit. The query credits (reiwand-ctl scene ask DIR credits) answers assets (path, kind, size, credited), the credits and the missing paths. A package that already credits someone, or whose origin is derived or curated, gets a warning at /manifest/credits in the problems list and in pack check while some of those files have no credit.

/manifest/strings has a table of its own for version 2 manifests: the languages (each with a switch that keeps its texts in locale/<language>.json), every key with a box per language, the missing ones in red with the summary at the top, the keys no text uses marked, a row to add a key with its first text, and the texts of the engine (reiwand.*, in English and Spanish) listed. Every text field has a Use a text by key button that offers the keys of the table and the engine's and sets the field to @key. The query strings (reiwand-ctl scene ask DIR strings) answers the languages, where each lives (places: manifest or file), the keys (used, texts by language, missing languages) and the engine texts. The writes to a locale file happen when the action is accepted, after the manifest checks pass, and are not part of undo (the manifest part of locale is).

The thumbnail and the animated preview of a scene can be captured instead of chosen from a file: Capture from the scene next to the picture chooser draws the scene at the second the preview is on and keeps the frame, and Record a preview records a few seconds from there as a gif, or as a lossless webp with the WebP box ticked; for a picture package the button keeps the picture and for a video package it draws the video; both run in the background (the editor shows it busy), draw with Renderer::stills (one view of the scene for all the frames) and store through the same path as thumbnail, so the size rules above apply. A web page keeps the file chooser. The animated webp is written by webp::animated, which wraps lossless frames in an animation container.

The photosensitive switch has a Measure the flashes button that draws 8 s of the scene at 15 frames a second, takes the brightness of a grid of 32 × 18 cells of every frame and feeds it to the FlashGuard the daemon uses to calm scenes that flash (more than three times a second over a tenth of the picture). When it flashes and photosensitive is not set, the problems list gets a warning at /manifest/photosensitive (while the scene and its properties stay as they were measured), and reiwand-ctl pack check measures a scene that does not declare itself photosensitive and prints the same warning. Sound, the pointer and the clock decide the real picture, so the measure is a hint, not a proof.

Every step of the history ends with the inputs and features the document needs, computed as reiwand-ctl pack build does: the inputs the scene uses are added to inputs (the ones an author declares, such as media or network, stay), an audio, pointer or clicks input that the scene used before the step and no longer uses goes, and requires.features becomes exactly the computed list, keeping requires.engine and a requires the author added empty to set it. Undo and redo restore both with the rest of the step, and setting, adding, removing or moving anything under /manifest/requires/features is refused, except adding or removing locale_files, which the author chooses (a check box under the computed list). The same step sets permissions.rgb of a scene while some layer has rgb on and drops it when none does, whatever the edit (the rgb action, a set, adding, copying or removing a layer); a web page keeps the switch of its preview and the Sends its colors to the RGB lighting box among its inputs, and the inspector does not offer permissions.rgb for a scene, which keeps it in step itself. A folder edited by hand may lack them: a missing input is an error and a missing feature a warning, and build and apply first record the step sync that fills them and save. Problems also cover the rules of features::check and its warnings (a declared audio, pointer, clicks, media or network input that nothing uses), the verdict of reiwand-ctl pack check for each platform that refuses the package or plays it without a feature (a warning at /manifest/requires/features), and previews over their size, format or length. Every field that version 2 requires and is missing is a problem of its own, listed together. Locale files, effect shaders and .glb models are read again only when their size or modification time changes, so editing a value never reads them.

A preset package (kind: preset) shows Publish as a preset under its settings: the steps of the query preset_steps (base, values, title, license, preview and a review without errors, each done or not), Edit… for the title and the license, Capture the thumbnail and Record a preview (gif, or webp with the WebP box), which draw the installed base scene with the values of the preset through shot with base, Choose a picture…, and Publish…, enabled when every step is done, which brings the steps of publishing. reiwand-ctl scene new DIR --from preset takes --base ID, --range, --values FILE, --license and --preview FILE to make the same package in one command.
